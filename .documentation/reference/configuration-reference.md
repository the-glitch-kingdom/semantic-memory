# Configuration reference

## Files

### `.claude-plugin/plugin.json`
Plugin manifest. Name, description, version, keywords.

### `.claude-plugin/marketplace.json`
Marketplace descriptor — lets `/plugin marketplace add` register this repo. Per project memory: `metadata.version` AND `plugins[0].version` must bump in lockstep with `package.json`.

### `.mcp.json` (per-project)
MCP server registration. Written by the SessionStart reconcile hook. Expected shape (v1.1.1+):
```json
{
  "mcpServers": {
    "semantic-vault": {
      "type": "stdio",
      "command": "node",
      "args": ["./node_modules/@theglitchking/semantic-memory/bin/semantic-memory",
               "--notes", "./path/to/vault"]
    }
  }
}
```
Mid-migration installs may have `@theglitchking/semantic-sidekick/bin/semantic-sidekick` instead — `findLocalBin` prefers the new path with legacy fallback. Gitignored by default. Regenerated on SessionStart by `hooks/reconcile.js`.

**Server names (v1.7.2):** the hooks search every entry whose name starts with `semantic-` and whose `args` include
`--notes`, so `semantic-memory` + `semantic-memory-docs` works as well as `semantic-vault` + `semantic-sidekick`.
Before 1.7.2 only `semantic-vault`, `semantic-sidekick` and `semantic-memory` were searched. An entry may also set
`"alwaysLoad": true` to keep all of that server's tools out of Claude Code's tool search; 1.7.2 already keeps
`search_hybrid` out of it, so this is rarely needed.

### `.claude/settings.json` (per-project)
Project-level Claude Code settings. Hooks auto-merge from plugin's `hooks/hooks.json`. Can override:
- `permissions.allow[]` / `permissions.deny[]`
- `env.<VAR>` — environment variables for hook/tool invocations
- `statusLine` — custom status bar command
- `hooks.<event>[]` — additional hooks beyond the plugin

### `.claude/CLAUDE.md` (per-project)
Repo-specific augmentation. In v1.2+, opens with a pointer to `<projectRoot>/AGENTS.md` as the primary contract. Contributes:
- Vault-first rule (Phase 1)
- Routing / mode indicator rule (Phase 4)

### `<projectRoot>/AGENTS.md` (v1.1+)
Canonical agent contract artifact with managed-block markers. Generated by `regenerate_contract`. Local Notes section outside the markers is preserved across regenerations. NOT gitignored — commit it. See [contract-guide.md](../operational/contract-guide.md).

### `<vault>/vault.schema.yml`
Per-vault schema override. If absent, the default from `src/core/schema-default.ts` applies. Install with `semantic-memory install-schema --notes <path>` or via the `install_schema` MCP tool.

### `<vault>/.semantic-sidekick-index/` — index artifacts (gitignored)
Path retains legacy name through all of v1.x per the v1.0 storage promise. v2.0 will move to `.claude/.semantic-memory/index/`.

- `hnsw.bin`, `hnsw-meta.json` — HNSW vector index.
- `embeddings.json` — per-chunk vectors, keyed by `<path>:<chunkIndex>`.
- `graph.json` — built graph.
- `meta.json` — model, dimensions, totalChunks, indexedAt.
- `docs.cache.json` — Phase 2 parsed-doc cache (drops hook latency 9x).

### `<vault>/log.md` — the durable state log (tracked with vault content)
Append-only. Format per entry:
```
- <iso-ts> — <kind>: <summary>
```yaml event
ts: <iso-ts>
kind: <kind>
summary: "<summary>"
payload:
  key: value
```
```

### `<vault>/proposals/<date>-<slug>.md` (v1.1+)
Review-first synthesize_note targets. Generated by `synthesize_note({proposal: true})`. Each carries `status: proposal` and `proposed_target` frontmatter; `synthesize_promote` moves them to canonical destinations. Commit when reviewed.

### `<vault>/dossiers/<slug>.md` (v1.5+)
Entity dossiers — one per critical component. `type: dossier`, fixed sections (Purpose / Failure modes / Knobs & commands / Incident log / Current state). Written by `manage_dossier` / `semantic-memory dossier init`; incidents and current-state accrete in place via `manage_dossier` actions `append_incident`/`set_state`. See [dossiers-guide.md](../operational/dossiers-guide.md).

### `<vault>/profile/speaker.md` (v1.5+)
Singleton speaker profile — how THIS human communicates. `type: profile`, `evergreen: true`, fixed sections (Severity calibration / Chronic omissions / Verbosity preference / Shorthand & terms). Written by `manage_profile` / `semantic-memory profile init`; sections updated via `manage_profile({action:"update_section"})`, typically triggered by a correction-cue capture. See [session-paging-guide.md](../operational/session-paging-guide.md).

### `<vault>/sessions/<session-id>.md` (v1.5+)
Session-paging digest proposals. Generated by `synthesize_note({from_session: true, proposal: true, proposal_subdir: "sessions"})` from the Stop hook's digest-paging instruction. Same proposal mechanics as `<vault>/proposals/` — `synthesize_promote` graduates a digest worth keeping. See [session-paging-guide.md](../operational/session-paging-guide.md).

### Repo config file — `<project>/.claude/.semantic-memory/config` (v1.7)

YAML. Missing or unparseable means `{}`.

```yaml
skill_loop: on              # on | off. Beats the SEMANTIC_MEMORY_SKILL_LOOP env for this repo.
skill_loop_consolidate: true  # turn on merging of overlapping learned skills (opt-in)
doc_search_redirect: off    # v1.7.2: turn off the PreToolUse doc-search redirect for this repo (on by default)
```

`semantic-memory skill-loop on|off --repo` writes `skill_loop`; `--clear` removes it so the global switch applies. Jev mode has no repo override (env only).

## Schema (`vault.schema.yml`) fields

Defaults — see `src/core/schema-default.ts` for the ground truth.

### `version` (number)
Schema format version. Current: 1.

### `provenance_fields` (string[])
Field names that constitute provenance. Default: `[sources, derived_from, last_verified, status, confidence]`.

### `status_enum` (string[])
Allowed values for `status` frontmatter. Default: `[draft, active, stale, deprecated, archived, proposal]` (proposal added in v1.1+).

### `confidence_enum` (string[])
Default: `[high, medium, low]`.

### `severity_enum` (string[])
For `gotcha` type. Default: `[low, medium, high, critical]`.

### `types` (map)
```yaml
types:
  <type-name>:
    description: str  # optional
    required: [<field>, ...]  # list of required frontmatter keys
```
Default types: `note`, `decision`, `gotcha`, `source`.

### `lint` (map)
```yaml
lint:
  missing_provenance:
    applies_to: [note, decision, gotcha]  # list of types to check
    severity: warn                         # warn | error
  stale:
    max_age_days: 180                      # 0 = disabled
    severity: warn
  schema_violations:
    severity: error                        # blocks apply_patch when validate=true
```

### `decay` (vault.schema.yml) — 🆕 v1.3+
Confidence decay down-weights `search_semantic`/`search_hybrid` results by time since a note's `last_verified` timestamp. It never removes notes from results — only ranks them lower, and only down to `floor`. `search_text`/`search_graph` are unaffected. It composes multiplicatively with `load_priority`.

```yaml
decay:
  enabled: true                 # false → byte-identical pre-v1.3 ranking
  default_half_life_days: 365   # multiplier = 0.5 ^ (age_days / half_life)
  per_type:
    decision: 365
    note: 365
    gotcha: 180
    source: null                # null = never decays
    proposal: 14
  floor: 0.1                     # notes never drop below this multiplier
  hotness_boost:
    enabled: false               # extend half-life for heavily-backlinked notes (opt-in, off by default)
    cap: 2.0
```

- **`enabled`** — master switch. `false` reproduces pre-v1.3 ranking byte-for-byte.
- **`default_half_life_days`** — half-life used for any type not listed in `per_type`. Multiplier formula: `0.5 ^ (age_days / half_life)`.
- **`per_type`** — per-note-type half-life override, keyed by frontmatter `type`. `null` for a type means it never decays (e.g. `source`).
- **`floor`** — minimum multiplier a decayed note can reach; decay ranks down, never to zero.
- **`hotness_boost`** — opt-in, off by default. When `enabled: true`, extends the effective half-life for heavily-backlinked notes, up to `cap`×.

**`last_verified`** is stamped at note creation and reset by the `verify_note` MCP tool (see [mcp-tools-reference.md](./mcp-tools-reference.md)) — it is **not** bumped by ordinary edits (`update_note`, `apply_patch`).

**`evergreen: true`** frontmatter field pins a note at multiplier `1.0` while its `last_verified` is within 365 days; after that it decays normally.

Unquoted YAML dates in frontmatter (e.g. `last_verified: 2026-01-01`) are handled correctly — parsed as a `Date` and normalized, not treated as a string parse error.

**CLI debugging:** `semantic-memory decay-config --notes <path>` prints the active config; `semantic-memory decay-trace <notePath> --notes <path>` prints the calculation for one note. See [cli-reference.md](./cli-reference.md).

### `telemetry` (vault.schema.yml) — 🆕 v1.3.1+

Selection-logging telemetry **observes** retrieval and citation behavior; it does not change ranking. `search_semantic`/`search_hybrid` log what they surface, `read_note` logs what actually gets read, and downstream tooling (the `decay_candidates` lint, and eventually v1.4 usage-feedback ranking) reads the log back.

```yaml
telemetry:
  enabled: true    # false → no selection.jsonl writes at all
```

- **`enabled`** — master switch, default `true`. Set `false` to disable all logging; existing log content is left in place, readers just see nothing new appended.
- **Log path:** `<project>/.claude/.semantic-memory/selection.jsonl` — local, append-only JSONL, gitignored by default, never transmitted anywhere.
- **What writes it:** `search_semantic`/`search_hybrid` (kind `"search"`, one entry per call, reusing the decay multiplier already computed per result) and `read_note` (kind `"selection"`, with `correlated: true` when the read path was in a preceding search's results within a 60s in-process window). `search_text`/`search_graph` are not logged.
- **What reads it:** `lint_vault({checks: ["decay_candidates"]})` (see [mcp-tools-reference.md](./mcp-tools-reference.md)) and `semantic-memory selection-stats --notes <path>` (see [cli-reference.md](./cli-reference.md#selection-stats-v131)). Both are no-ops on an empty/missing log.
- **Fail-safe:** logging is awaited (durable, not fire-and-forget), but the writer never throws — a logging failure can never fail the underlying search/read call.
- **Feeds:** the v1.4 usage-feedback ranking work will consume this same log; v1.3.1 only produces it.

See [v1-3-1-telemetry.md](../changelog/v1-3-1-telemetry.md) for the full writeup, including the privacy stance.

### `path_class` (vault.schema.yml) — 🆕 v1.4+

Down-weights whole path regions in `search_semantic`/`search_hybrid` ranking by glob-matching a note's path against an ordered rules list. Composes multiplicatively with `decay` and `load_priority`.

```yaml
path_class:
  enabled: true
  rules:
    - glob: "archive/**"
      multiplier: 0.3
```

- **`enabled`** — master switch for path-class down-weighting.
- **`rules`** — ordered list of `{ glob, multiplier }`. `glob` matches against the note's vault-relative path; `multiplier` scales the ranking score the same way `decay`'s multiplier does. **First matching rule wins** — rules are evaluated in list order and later rules are not consulted once one matches (no stacking multiple rules on one note).
- **Related env var:** `SEMANTIC_MEMORY_INJECT_MIN_SCORE` (default `0.35`) score-gates the `<vault-context>` hook injection — results scoring below this threshold, after decay + `path_class` + `load_priority` are applied, are not injected into the prompt/session-start context regardless of the hook's top-K limit. See [Environment variables](#environment-variables) above.

See [mcp-tools-reference.md](./mcp-tools-reference.md) for the search tools this affects.

### `usage_boost` (vault.schema.yml) — 🆕 v1.5+

Boosts `search_semantic`/`search_hybrid` results that get CITED (via `read_note`) after retrieval, per the v1.3.1 selection log. Bounded by `cap` to stop a feedback-runaway loop (cited → ranks higher → cited more). Composes multiplicatively with `decay`, `path_class`, and `load_priority` at the same rank site.

```yaml
usage_boost:
  enabled: true
  cap: 1.5            # max multiplier a note can earn from citations
  per_citation: 0.1   # multiplier += per_citation × citation_count, then capped
```

- **`enabled`** — master switch. `false` reproduces byte-identical pre-v1.5 ranking.
- **`cap`** — maximum multiplier a note can earn purely from citations, default `1.5`.
- **`per_citation`** — multiplier increment per citation before capping, default `0.1`. Formula: `multiplier = min(cap, 1 + citations × per_citation)`.

A no-op until the selection log actually has citations (fresh vault, or a note that's never been read after appearing in results). The citation snapshot is TTL-cached for 15s and refreshed before each search batch, so within-session citations take effect without a process restart.

Boosted results carry a `usage: { citations, multiplier }` block, the same shape convention as `decay`.

**Complementary signal — decoys.** Notes retrieved 3+ times but never cited are surfaced by the opt-in `lint_vault({checks:["decoys"]})` check — never auto-down-ranked (down-rank on evidence, never on ambiguous inference). See [mcp-tools-reference.md](./mcp-tools-reference.md), [usage-feedback-guide.md](../operational/usage-feedback-guide.md).

### `tools` (vault.schema.yml) — 🆕 v1.4+

Controls whether the MCP server registers a reduced tool surface while the project is in `outage-silence` mode.

```yaml
tools:
  conditional: false   # default off
```

- **`conditional`** — when `true`, the server registers a reduced search/read surface for the duration of `outage-silence` mode. Default `false` — the full tool surface is always registered.
- **Gotcha:** the registered tool surface is fixed at MCP server start/connect time. A mid-session `/mode outage-silence` switch does **not** re-register tools — the reduced surface only takes effect the next time the server (re)starts while already in that mode. Don't expect tools to vanish mid-session purely from a mode flip.

## Plugin auto-update policy (`semantic-memory.json`)

Written by the plugin runtime to `.claude/semantic-memory.json` (was `.claude/semantic-sidekick.json` pre-v1.1.1):

```json
{ "updatePolicy": "nudge" }
```

Values:
- `nudge` (default) — SessionStart shows a one-line upgrade reminder when a newer version is on npm.
- `auto` — auto-runs `npm update` on SessionStart if a newer version exists.
- `off` — no upgrade checks.

Change via `/policy <value>` or edit the file directly.

The legacy `.claude/semantic-sidekick.json` is still read as a fallback for mid-migration installs.
