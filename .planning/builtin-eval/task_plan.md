# Task Plan: builtin-eval

## Goal
Ship semantic-memory#56 as v1.13.0: `semantic-memory eval` measures retrieval on the user's own vault through the
live search path. It covers:
- question sets: hand-written, generated by the host agent (blind), and negatives;
- answer @1/@3, found@k, MRR, per tier, negatives flagged, false flags, "#1 + related", p50/p95;
- `--baseline` / `--check` floors with a noise band;
- "all" vs "clean" reporting.

The engine in `test/retrieval-eval/` moves into `src/` so the repo's own eval and the shipped command are the same
code. One PR from `feat/builtin-eval`. Series step 1. Every missed target is stated in the PR.

## Rules for every phase
- **Verify before ticking.** Confirm in code, or with a test, that a box is actually done before ticking it.
- **Same numbers.** Moving the engine must not change any number in `npm run eval`; the existing tests are the guard.
- **The eval never changes the user's index or logs.** It refuses to run with no index ("run --reindex"). It opens
  the index with the model, pooling and prompt recorded in its `meta.json`, so a model mismatch never re-embeds. Its
  searches are never logged (`ServerOptions.telemetry: false`).
- **Offline CI.** Generation uses `runClaude`; CI uses the fake `test/bin/claude` (`SEMANTIC_MEMORY_CLAUDE_BIN`).
- **Reuse.** `runEval`, `runFacetEval`, `facetRank`, `parseGolden`, `formatArm` (test/retrieval-eval/eval.ts);
  `createServer` + `InMemoryTransport` (test/retrieval-eval/harness.ts); `runClaude` (src/core/claude-run.ts); the
  prompt pattern of `src/core/skill-eval/prompts/`; the sha256 split of `skill-eval/sets.ts`; the step sampling of
  `bm25SelfTop`. No new dependencies.
- **Works without hit-em-with-the-docs.**

## Decisions Made
- Default eval dir is `.claude/.semantic-memory/eval/` (as #56 says), which is gitignored; `--dir` points at a
  committed folder for teams that want shared floors. Documented.
- Negatives carry `negative_kind` so #57's identifier negatives are reported apart from topic negatives.
- The usage-derived set comes from #59's `usage-set`; this plan does not port `mine-selection.mjs`.
- "Re-run on every release" means this repo's CI and release checklist; no auto-run for users after update.

- `eval generate` is a subcommand of `eval`: commander gives `--notes` to a parent that declares it, so `eval`'s `--notes` is checked in its action (not `requiredOption`) and `enablePositionalOptions()` is set on the program and on `eval`.
